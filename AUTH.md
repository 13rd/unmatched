# Система авторизации и сохранения сессий

## Описание
Реализована полная система авторизации пользователей с сохранением сессий, которая позволяет игрокам не терять свою роль и прогресс при перезагрузке страницы.

## Основные компоненты

### 1. Страница авторизации (auth.html)
- Простая форма ввода имени игрока
- Валидация: имя от 2 до 20 символов
- Автоматическая генерация уникального userId
- Сохранение данных в localStorage

### 2. Генерация уникального ID
```javascript
userId = 'user_' + Date.now() + '_' + Math.random()
```
- Уникальный ID для каждого пользователя
- Сохраняется в localStorage
- Используется для идентификации при переподключении

### 3. Сохранение сессии
В localStorage сохраняются:
- `userId` - уникальный идентификатор пользователя
- `username` - имя игрока
- `loginTime` - время входа

В sessionStorage сохраняются:
- `roomCode` - код текущей комнаты
- `gameSettings` - настройки игры (без больших данных)

## Как это работает

### Первый вход
1. Пользователь открывает сайт → перенаправление на `auth.html`
2. Вводит имя → генерируется userId
3. Данные сохраняются в localStorage
4. Перенаправление на `setup.html`

### Переподключение
1. Пользователь перезагружает страницу
2. Система проверяет наличие userId и username в localStorage
3. Если данные есть → автоматический вход
4. Отправка `user-auth` на сервер с сохраненными данными
5. Сервер восстанавливает роль игрока в комнате

### Серверная логика

#### Хранилище пользователей
```javascript
users = Map {
  userId -> {
    socketId: текущий socket.id,
    username: имя игрока,
    roomCode: код комнаты или null
  }
}
```

#### Хранилище комнат
```javascript
rooms = Map {
  roomCode -> {
    settings: настройки игры,
    chips: фишки на поле,
    cards: карты в игре,
    players: [userId1, userId2, ...],
    playerRoles: {
      userId1: 'player1',
      userId2: 'player2'
    }
  }
}
```

#### Переподключение игрока
1. Игрок отключается → socketId обновляется, но userId остается
2. Игрок переподключается → сервер находит userId в users
3. Восстанавливается роль из room.playerRoles[userId]
4. Игрок продолжает игру с той же ролью

## Преимущества

### ✅ Сохранение прогресса
- Перезагрузка страницы не сбрасывает роль игрока
- Игрок остается Игроком 1 или Игроком 2
- Все карты и фишки остаются на месте

### ✅ Идентификация игроков
- Каждый игрок имеет уникальный ID
- Имя игрока отображается в интерфейсе
- Роль игрока видна в правом верхнем углу

### ✅ Безопасность сессии
- userId генерируется на клиенте
- Сервер не хранит пароли
- Простая система для локальной игры

## Интерфейс

### Информация о пользователе
В правом верхнем углу отображается:
- Имя игрока
- Роль (Игрок 1 / Игрок 2 / Наблюдатель)
- Кнопка "Выйти"

### Выход из системы
При нажатии "Выйти":
1. Подтверждение действия
2. Очистка localStorage (userId, username)
3. Очистка sessionStorage (roomCode, settings)
4. Перенаправление на auth.html

## Использование

### Первый запуск
1. Откройте `auth.html` или главную страницу
2. Введите ваше имя
3. Нажмите "Войти в игру"
4. Создайте или присоединитесь к комнате

### После перезагрузки
1. Просто обновите страницу (F5)
2. Вы автоматически войдете под тем же именем
3. Если вы были в комнате, ваша роль сохранится
4. Все карты и фишки останутся на месте

## Технические детали

### Проверка авторизации
Каждая страница проверяет наличие userId:
```javascript
if (!localStorage.getItem('userId')) {
    window.location.href = 'auth.html';
}
```

### Отправка данных на сервер
```javascript
socket.emit('user-auth', {
    userId: localStorage.getItem('userId'),
    username: localStorage.getItem('username')
});
```

### Восстановление роли
```javascript
if (room.playerRoles[userId]) {
    playerRole = room.playerRoles[userId];
    // Игрок переподключается с той же ролью
}
```

## Ограничения

- Данные хранятся локально в браузере
- При очистке кэша браузера данные теряются
- Нет защиты паролем (подходит для локальной игры)
- Один браузер = один пользователь
